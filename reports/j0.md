## FAIT

- Projet d'exemple normatif `examples/jest-project/` (C.0), 12 tests Jest verts sans Varia.
- Sonde (`spike/runtime/probe.cjs`) : enveloppement des exports, `AsyncLocalStorage` pour la
  profondeur, état sur `globalThis.__varia`, sérialisation étiquetée (§10.7), redaction dans la sonde
  avant écriture, empreinte d'arguments, application d'**une** mutation sur copie profonde, journaux
  JSONL append-only (`appendFileSync`), erreurs sérialisées avec `constructorChain`.
- Transform D1 (`spike/runtime/transform.cjs`) : délègue au transform d'origine (babel-jest par défaut,
  ts-jest via `preset`), ajoute le pied de module `__varia.wrapExports` après la dernière ligne
  (source maps intactes), clé de cache salée par run.
- Orchestrateur (`spike/src/`) : config Jest générée **hors du projet** (dans le stockage utilisateur),
  cache Jest propre au run, sortie JSON de Jest lue sur stdout, 1 mutation = 1 processus limité au
  test visé, timeout avec mise à mort du groupe de processus, catalogue, stratégies J0 (type, null,
  undefined, empty, boundary + valeurs déclarées), plan déterministe trié, oracle (§18.3/18.4),
  intégrité git + manifeste.
- Scénarios J0-1 à J0-18 automatisés et verts ; J0-19/J0-20 explorés et figés en tests.
- Preuve que les tests peuvent échouer : `scripts/mutation-check.mjs` sur 5 mutations du code.
- Identité de marque (logos fixe/animé, dérivés, `npm run brand`, aperçus réels), clés i18n de signature.

## PAS FAIT

- Pas de base SQLite, CLI, dashboard (hors périmètre J0).

## NON SUPPORTÉ (constaté)

- **ESM natif** sous Jest (J0-20) ⇒ J2 ; en J1, `doctor` doit répondre `UNSUPPORTED_PROBE`.
- **Classes exportées** : non enveloppées, listées `unsupported` (CDC B : ciblage limité en J2).
- **Cibles mockées** : non observées ; `MOCKED_TARGET` seulement déductible (cible découverte ailleurs, absente du test).
- **Appels internes au même module** (J0-17) : non observés, par construction (§10.0).

## LIMITATIONS

- `fetchUser` n'est pas déclarée `async` (impossible de lever synchroniquement sinon) — D-005.
- `exitOn("boom")` n'est pas dans les catalogues du §13.3 : valeur **déclarée** (`extraValues`) — D-006.
- `testId` = fichier + nom complet résolu + rang d'homonyme ; l'indice de cas `test.each` est porté
  par le titre résolu (cas de même titre ⇒ rang d'homonyme).
- Les scénarios J0 ont été écrits juste après le premier prototype de sonde (pas strictement
  « test d'abord ») ; chacun a ensuite été vu échouer par mutation (ci-dessus) ou en développement
  (ex. J0-8/J0-14 en échec avant l'ajustement de la sélection, J0-11 en échec révélant D-007).
